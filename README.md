# 문양 좌표 수집 도구

`index.html`을 Chrome 또는 Edge에서 열거나 배포된 GitHub Pages 링크를 사용한다. 설치가 필요 없는 단일 HTML이다. 서버에는 수집 데이터를 보내지 않는다. Safari 계열은 WebKit 자동 검증과 실제 Safari 확인을 구분한다.

공유 주소: https://snoopuppy582.github.io/marginalia-drawing-collector/

배포 저장소는 `snoopuppy582/marginalia-drawing-collector`이며 이 폴더의 `index.html`, `README.md`와 빈 `.nojekyll`만 공개한다. 게임 저장소와 작성자의 JSON은 업로드하지 않는다. 원본은 이 폴더에서 관리하고 배포 복사본에서 별도로 수정하지 않는다.

## 사용

1. 성씨 영어 + 회차를 입력한다. 예: `Moon1`, 같은 사람의 다음 수집은 `Moon2`. 성씨가 겹치면 `KimA1` / `KimB1`처럼 식별 부분을 구분하고 계속 같은 표기를 사용한다. 문양당 10개, 총 50개가 기본이다.
2. 왼쪽 버튼으로 그린다. 버튼을 떼면 획만 끝난다. **X는 두 획을 그리고 Enter 또는 ‘기록하고 다음’**을 누른다.
3. 가로선 → 세로선 → 원 → X → 하트 순서로 진행한다. 그리는 중에는 마지막 획 또는 현재 그림을 지울 수 있다. 잘못 등록했다면 **이전 그림 다시 그리기**를 여러 번 눌러 이전 제출을 한 장씩 확인한다. 위에는 **그려야 했던 문양과 순번**, 아래에는 **실제로 제출한 그림**이 나타난다. 여섯 장 전에 잘못 그린 그림도 찾아 고칠 수 있다.
4. **완료하고 JSON 다운로드**를 누르고 다운로드 폴더나 브라우저 다운로드 목록에서 파일을 확인해 카톡에 첨부한다. 중간에도 저장 가능하며, 그리던 그림도 포함된다. 페이지가 로컬 파일 저장 완료를 확인할 수 있는 것은 아니므로 UI는 다운로드 요청과 실제 파일 확인을 구분한다.
5. JSON을 다시 불러오면 별도의 브라우저 보관본에서 이어한다. 원래 보관본을 덮어쓰거나 두 사람의 데이터를 자동 합치지 않는다.

이전 그림을 보기만 하면 기록은 바뀌지 않는다. 틀린 그림에서 **이 그림 다시 그리기 → 새로 그리기 → 수정한 그림 저장**을 누르면 그 순번의 기록만 교체한다. 다른 그림, 제출 순서, 수집 개수, 당시 크기 안내는 유지한다. **다음 그림 보기**로 뒤쪽 기록도 확인하며, 끝나면 **수집하던 곳으로 돌아가기**를 누른다. 수집 중이던 미완성 그림도 별도로 보관해 돌아왔을 때 그대로 보여 준다.

수정을 시작한 뒤에는 저장하거나 **수정 취소**로 원래 제출을 복원한 후 이동한다. 수정 중인 그림과 확인 위치는 새로고침·JSON 백업/불러오기에도 유지된다. 미완성 수정은 완료 샘플에 적용하지 않는다. **수정을 마친 뒤 새로 받은 최종 JSON만 전달한다.** 이미 받은 파일은 자동으로 바뀌지 않으며, 새 그림에는 새 ID를 부여한다. 이전 파일과 최종 파일을 함께 제출하면 폐기한 옛 그림이 별도 샘플로 집계될 수 있으니 최종 파일만 보낸다.

가능하면 평소 게임에서 쓰는 마우스로 자연스럽게 그린다. 인식 결과나 따라 그리는 배경 도안은 제공하지 않는다. 모양이 덜 예쁘다는 이유로 반복 삭제하지 않는다. 수집 중 창 크기를 바꾸면 현재 그림에 좌표가 섞이지 않도록 이어 그리기를 잠근다. 그 그림을 기록하거나 다시 그린 후 계속한다.

## 보관 방식

- 획을 그리는 동안 약 400ms마다, 획 종료와 샘플 기록 시에는 즉시 IndexedDB에 보관한다. 브라우저가 강제 종료된 순간의 마지막 입력까지 보장하는 것은 아니다.
- 새로고침 후 같은 HTML·브라우저에서 자동 복원한다. **브라우저 보관은 휴대 가능한 파일 백업이 아니다.** 브라우저 데이터 삭제, 다른 브라우저 또는 HTML 경로 이동에 대비해 JSON을 내려받는다.
- 저장 실패나 용량 제한이 발생하면 명시적으로 경고한다. 현재 창의 좌표를 JSON으로 내보낼 수 있다.
- 같은 기록을 여러 탭에서 동시에 수정하면 revision 검사로 덮어쓰기를 막는다. 충돌한 탭에서는 현재 내용을 JSON으로 내보내 새 보관본으로 불러온다.
- 데이터는 외부로 전송하지 않는다. HTML과 테스트만 Git 관리 대상이며, 수집 파일을 소스 폴더에 넣지 않는다. 실험 파일은 저장소의 무시된 `.codex-local/drawing-dataset/` 또는 개인 다운로드 폴더에 보관한다.

## JSON 규약 v1

`format: marginalia-gesture-dataset`, `schemaVersion: 1`, 새 수집은 `protocol.id: five-glyphs-x-size-v2`, `collectorVersion: 1.3.0`. 기존 `five-glyphs-x-v1` 파일도 원본을 바꾸지 않고 불러온다. 새 수집의 문양별 크기 안내는 편한 크기 4개 / 작게 3개 / 크게 3개이며, 다른 목표 개수는 같은 비율로 나눈다. 문양을 따라 그리는 강제 크기 상자는 쓰지 않는다.

| glyphId | 의도한 문양 | 게임의 기존 patternId | 비고 |
| --- | --- | --- | --- |
| horizontal | 가로선 | cancellation-line | 취소선 |
| vertical | 세로선 | ink-eruption | 잉크 분출 / 먹빛 파열 |
| circle | 원 | fire-circle | 시간의 원 |
| x | X | ink-slash | 게임과 동일하게 서로 교차하는 두 획 |
| heart | 하트 | frost-triangle | 하트 여왕의 판결. 레거시 이름을 문양으로 해석하지 않음 |

- `session`: 작성자 번호, 안정적인 수집 ID, 시작/수정 시각, 목표 개수, 입력 도구. 새 파일은 소문자 `authorId`와 숫자 `attempt`도 저장한다. `Moon1`과 `Moon2`를 다른 작성자로 분리해 평가하지 않는다. 기존 P01은 건호의 예비 수집으로 별도 매핑한다.
- `samples[]`: 안정적인 샘플 ID, 정답 `glyphId`, 스킬 대응, 문양 버전, 시작/기록 시각, 마지막 좌표까지의 시간, 입력 영역, 획 배열, 입력 중단/영역 이탈 플래그. 새 수집은 `sizeInstruction` (`natural`, `small`, `large`)를 보존하며 실제 크기는 좌표에서 따로 계산한다.
- `draft`: 아직 기록 버튼을 누르지 않은 그림. 완료 샘플 수와 평가 데이터에 포함하지 않는다.
- `review` (이전 기록 확인 중에만 존재): 확인할 완료 기록의 `sampleId`, 수정 여부 `editing`, 수정 중인 `draft`. `samples`의 원래 기록과 수집용 `draft`를 덮어쓰지 않는다. ‘수정한 그림 저장’에서만 해당 `samples` 항목을 교체하며, 수집으로 돌아가면 `review`를 제거한다. 평가에는 완료된 `samples`만 사용하므로 미완성 수정이 있는 백업을 최종 제출하지 않는다.
- `canvas.width/height`: 해당 그림을 시작한 순간 그리기 영역의 CSS 픽셀 크기. `devicePixelRatio`는 표시 배율이며 좌표에 곱하지 않는다.
- `strokes[].id`: 1부터 시작하는 획 번호. `pointerType`은 브라우저가 관측한 `mouse`, `pen`, `touch` 등이다. 마우스와 터치패드는 이 값만으로 구분할 수 없어 `session.declaredInputDevice`도 보관한다.
- `points[]`: `{x, y, t}`. 좌상단 원점, 오른쪽 +x, 아래쪽 +y, CSS 픽셀 좌표. `t`는 그림 시작 이후의 밀리초다. 획 사이 대기 시간도 포함된다. 좌표·시간을 소수점 셋째 자리까지 보관한다. 공간 리샘플링, 평활화, 크기 정규화는 하지 않는다. 브라우저가 제공하는 병합 전 포인터 이벤트도 가능한 경우 수집한다.
- 획은 배열로 분리하며 `NaN`이나 가짜 연결점을 쓰지 않는다. 취소·입력 중단은 플래그로 남긴다. 인식 결과를 기준으로 샘플을 제외하지 않는다.
- 동일 JSON을 여러 번 가져오면 로컬 보관본은 별개지만 논리적인 세션·샘플 ID는 보존된다. 나중에 파일을 합칠 때 샘플 ID로 중복을 제거한다.

## 향후 비교

원본 좌표를 공통 입력으로 재생해 기존 방식과 $P+를 비교한다. Unity에 넣을 때 y축을 뒤집고, 각 알고리즘의 입력 전처리를 명시적으로 맞춰야 한다. 현재 게임의 화면 가로·세로별 정규화와 일반적인 종횡비 유지 정규화를 혼동하지 않는다. 비교 대상 양쪽에 X 템플릿을 제공해야 하며, X로 문양을 바꾼 효과와 알고리즘 변경 효과를 구분한다.

이 도구의 첫 데이터는 **P01 한 사람의 예비 수집**이다. 여러 사람에게 일반화되는 인식률로 보고하지 않는다. 이후 작성자 단위로 참조용·조정용·평가용 데이터를 분리하고 평가 샘플을 템플릿으로 재사용하지 않는다. 브라우저 수집 성능과 Unity 실제 플레이의 인식·발동 성공률도 구분한다.

## 자동 확인

`node verify.cjs`로 별도의 임시 브라우저 컨텍스트에서 획 입력, X 두 획, 여섯 장 뒤로 가기·당시 그림 표시·선택 기록만 교체·수집 중인 그림 보호·수정 취소, JSON 다운로드/불러오기, 새로고침 복원, 작성자 분리, 잘못된 JSON, 저장 장애, 탭 충돌을 확인한다. Playwright가 필요하다. 번들 패키지를 쓸 때 `NODE_PATH`를 그 경로로 지정한다. 브라우저가 별도로 설치되어 있으면 `COLLECTOR_BROWSER`를 해당 엔진 실행 파일의 절대 경로로 지정할 수 있다. 테스트는 실제 사용자 브라우저 프로필과 수집 기록을 사용하지 않는다.

`COLLECTOR_ENGINE=webkit`으로 WebKit에서도 같은 검사를 실행한다. 실제 macOS/iOS Safari 확인과 WebKit 자동 검증은 구분한다. `COLLECTOR_LEGACY_DATASET`에 예전 JSON 경로를 지정하면 좌표를 바꾸지 않는 불러오기·내보내기도 확인한다.

2026-10-15 Chrome 155 / WebKit 26.5에서 이전 기록 탐색·수정과 원본 P01 호환을 포함한 18개 검사 묶음을 통과했다. 실제 macOS/iOS Safari에서는 아직 확인하지 않았다.
